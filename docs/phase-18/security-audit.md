# Phase 18 — System Security Audit

**Project:** ToothCare Hub — Dental Appointment and Clinic Management System  
**Scope:** React/Vite frontend, native PHP 8.5 REST API (`/api/v1`), MySQL 8.x schema/queries, Node.js/Socket.IO real-time service, PHPMailer outbox worker, Nginx reverse proxy, Docker Compose, and GitHub Actions CI.

---

## 1. Existing Controls Verified

- **Authentication & Sessions:** `password_hash(..., PASSWORD_DEFAULT)` (`bcrypt`), `session_regenerate_id(true)` on login, sliding/idle session expiration (`AuthService::isCurrentSessionExpired()`), `HttpOnly` + `SameSite=Lax` cookies, single-use SHA-256-hashed email verification and password reset tokens, and rate limiting on login, registration, resend verification, and password reset.
- **Authorization & DRBAC:** Server-side `AuthenticationMiddleware` and `AuthorizationMiddleware` with granular permission slugs (`appointments.view`, `treatment_records.create`, `users.manage`, `email_outbox.retry`, etc.), super-admin lockout prevention, and ownership enforcement on patient/dentist resources.
- **File Uploads:** `AvatarStorageService` enforces 2 MB cap, `finfo` MIME validation (`image/jpeg`, `image/png`, `image/webp`), `getimagesize()` image-type verification, randomized 32-hex filenames (`bin2hex(random_bytes(16))`), storage outside web root (`backend/storage/uploads/avatars`), and `X-Content-Type-Options: nosniff`.
- **SQL & Output Security:** Parameterized PDO prepared statements across repositories; React default escaping with zero `dangerouslySetInnerHTML` or `eval()` in production frontend source.
- **Real-Time & Internal Isolation:** Short-lived single-use Socket.IO tickets (`POST /api/v1/realtime/ticket`), HMAC-SHA256 signed internal verification (`/api/v1/internal/*`) blocked `403` on Nginx public edge port `80` and routed only on internal port `8081`.
- **Container & Runtime Hardening:** PHP pinned to `php:8.5.12-fpm-alpine3.24` (`expose_php = Off`, `session.upload_progress.enabled = Off`), Node.js `realtime` runs as non-root `USER node` on `node:24-alpine`.

## 2. Confirmed Security Findings Register

| ID | Severity | Component | Evidence | Impact | Remediation | Status |
|---|---|---|---|---|---|---|
| **F-01** | **High** | `backend/src/Middleware/CsrfMiddleware.php:28`, `backend/src/Core/Application.php:62-66` | `CsrfMiddleware` ran globally before route-level `AuthenticationMiddleware` without starting the PHP session when the `toothcare_session` cookie was present, causing `session_status() === PHP_SESSION_ACTIVE` to evaluate false and skip CSRF validation on browser mutations. | Authenticated browser sessions vulnerable to cross-site request forgery on unsafe HTTP methods. | Hydrate PHP session in `CsrfMiddleware` whenever the configured session cookie is present; enforce `X-CSRF-Token` whenever `$_SESSION['csrf_token']` or `$_SESSION['user_id']` is set; exempt only `/api/v1/internal/*` (HMAC-signed). | **REMEDIATED & TESTED** |
| **F-02** | **High** | `backend/src/Routes/api.php:75`, `backend/src/Controllers/UserController.php:449-462` | `GET /api/v1/users/{id}/avatar` had no `AuthenticationMiddleware` and returned any user's avatar (including `PATIENT` photos) with `Cache-Control: public, max-age=3600`. | Unauthenticated enumeration and disclosure of patient/staff profile photos by sequential user ID. | Added `AuthenticationMiddleware` on `/users/{id}/avatar`, enforced owner or `ADMIN`/`RECEPTIONIST`/`DENTIST` check in `UserController::serveAvatar()`, changed cache header to `private, max-age=3600`, and updated OpenAPI spec. | **REMEDIATED & TESTED** |
| **F-03** | **High** | `backend/src/Core/Logger.php:25-41` | `Logger::SENSITIVE_KEYS` omitted `password_hash`, `session_id`, `verification_token`, `reset_token`, `ticket`, `smtp_password`, `realtime_internal_secret`, `email_payload_key`, `backup_encryption_key`, and clinical fields (`clinical_notes`, `treatment_notes`, `diagnosis`, `medical_history`, `medical_alerts`, `allergies`). | Risk of sensitive credentials or patient clinical data leaking into structured application logs if passed in exception/context arrays. | Expanded `SENSITIVE_KEYS` and added suffix-based redaction (`_password`, `_secret`, `_token`, `_hash`, `private_key`, `_encryption_key`). | **REMEDIATED & TESTED** |
| **F-04** | **Medium** | `backend/src/Services/DatabaseBackupService.php:746-774` | `$targetDatabase` was interpolated into `CREATE DATABASE IF NOT EXISTS \`{$targetDatabase}\`` and CLI `exec()` without strict identifier validation. | Potential SQL/command injection if an untrusted database name were ever passed to restore routines. | Added `DatabaseBackupService::validateDatabaseIdentifier()` enforcing `/^[A-Za-z0-9_]{1,64}$/` before SQL or CLI use. | **REMEDIATED & TESTED** |
| **F-05** | **Medium** | `backend/src/Routes/api.php:264` | `POST /api/v1/realtime/ticket` had no route-level rate limiting middleware. | Authenticated abuse could spam ticket generation and database writes. | Attached `RateLimitMiddleware::perMinute(60, 'realtime_ticket')` with standard `X-RateLimit-*` headers. | **REMEDIATED & TESTED** |
| **F-06** | **Medium** | `nginx/conf.d/toothcare.conf`, `nginx/snippets/security-headers.conf`, `monitoring/prometheus/prometheus.yml` | `/api/v1/metrics` was accessible on public Nginx port `80`; `security-headers.conf` lacked `Content-Security-Policy: frame-ancestors 'self'` and `Cross-Origin-Opener-Policy`, and included deprecated `X-XSS-Protection`. | Operational metrics exposed publicly; missing modern clickjacking/isolation headers. | Blocked `/api/v1/metrics` (`403`) on public port `80`, exposed it only on internal port `8081`, updated Prometheus target to `nginx:8081`, and modernized `security-headers.conf`. | **REMEDIATED** |
| **F-07** | **Medium** | `compose.yaml:109`, `compose.prod.yaml:21` | `phpmyadmin` ran by default in base `compose.yaml` (port `8085`), and `compose.prod.yaml` did not explicitly set `SESSION_COOKIE_SECURE: "true"`. | Risk of exposing phpMyAdmin or sending session cookies over non-TLS in production deployments. | Moved `phpmyadmin` to `profiles: ["tools"]` in `compose.yaml` and explicitly enabled `SESSION_COOKIE_SECURE: "true"` and `SESSION_COOKIE_SAMESITE: "Lax"` in `compose.prod.yaml`. | **REMEDIATED** |
| **F-08** | **Low** | `nginx/conf.d/toothcare.conf` | TLS (`443`), HTTP->HTTPS redirect, and `Strict-Transport-Security` require deployment-specific TLS certificates mounted in `/etc/nginx/ssl`. | Production transport encryption depends on host/ingress TLS termination configuration. | Documented in `production-readiness-checklist.md`; must be configured with valid CA certificates before production launch. | **ACCEPTED RISK (Pre-Prod Deployment Gate)** |
