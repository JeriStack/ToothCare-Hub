# API Contract Specification

## 1. Protocol and Base URL

All REST API endpoints are served over HTTPS (HTTP allowed only in isolated local development) and versioned under the `/api/v1` namespace.

```text
Base URL: /api/v1
Format:   application/json; charset=UTF-8
```

---

## 2. Standard Response Envelopes

Every JSON API response conforms to a unified 3-key envelope containing `data`, `meta`, and `error`.

### 2.1 Standard Success Envelope

```json
{
  "data": {
    "status": "ok",
    "service": "toothcare-backend",
    "environment": "development",
    "timestamp": "2026-11-05T19:20:00+08:00"
  },
  "meta": {
    "request_id": "3c26210f-6fb6-4556-9e90-c2d96abcf76a"
  },
  "error": null
}
```

When listing paginated resources, `meta` includes the pagination object:

```json
{
  "data": [
    { "id": 1, "name": "Dental Checkup & Consultation", "price": "500.00" }
  ],
  "meta": {
    "request_id": "3c26210f-6fb6-4556-9e90-c2d96abcf76a",
    "pagination": {
      "current_page": 1,
      "per_page": 20,
      "total_items": 45,
      "total_pages": 3
    }
  },
  "error": null
}
```

### 2.2 Standard Error Envelope

```json
{
  "data": null,
  "meta": {
    "request_id": "3c26210f-6fb6-4556-9e90-c2d96abcf76a"
  },
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "The submitted data is invalid.",
    "details": {
      "email": ["A valid email address is required."],
      "phone_number": ["The phone number format must follow E.164 (+63...)."]
    }
  }
}
```

## 3. Request Headers

| Header | Type | Description |
|---|---|---|
| `X-Request-ID` | String (UUID or alphanumeric max 64 chars) | Optional client correlation ID. If omitted or invalid, generated by the backend and returned in response headers and `meta.request_id`. |
| `Content-Type` | `application/json` | Required for all state-changing requests (`POST`, `PUT`, `PATCH`) with a payload body. |
| `X-CSRF-Token` | String (64-char hex) | Required for state-changing requests when an authenticated session is active. |
| `Origin` | String | Checked strictly against `CORS_ALLOWED_ORIGINS`. |

## 4. HTTP Status Code Mapping

| Status Code | Code Constant | Usage in ToothCare Hub |
|---|---|---|
| `200 OK` | — | Successful resource retrieval, update, or operation returning a body. |
| `201 Created` | — | Resource created successfully (e.g., appointment requested, account created). |
| `204 No Content` | — | Successful operation with empty body (OPTIONS preflight). |
| `400 Bad Request` | `BAD_REQUEST`, `MALFORMED_JSON` | Syntactically invalid request, unparseable JSON body. |
| `401 Unauthorized` | `UNAUTHENTICATED` | Missing, expired, or invalid session cookie. |
| `403 Forbidden` | `FORBIDDEN`, `CSRF_TOKEN_INVALID` | User lacks role permission, or CSRF token is invalid/missing. |
| `404 Not Found` | `NOT_FOUND` | Resource ID or API route does not exist. |
| `405 Method Not Allowed` | `METHOD_NOT_ALLOWED` | HTTP method not permitted on path; includes `Allow` header. |
| `409 Conflict` | `CONFLICT` | Slot double-booking, status state machine violation, email already registered. |
| `413 Payload Too Large` | `PAYLOAD_TOO_LARGE` | Request body exceeds configured limit (default: 1MB). |
| `415 Unsupported Media Type` | `UNSUPPORTED_MEDIA_TYPE` | Non-JSON `Content-Type` sent on state-changing endpoint with body. |
| `422 Unprocessable Entity` | `VALIDATION_ERROR` | Semantic validation failed (e.g. invalid date, short password). |
| `500 Internal Server Error` | `INTERNAL_SERVER_ERROR` | Unhandled server error. Public response contains no internal paths or stack traces. |
| `501 Not Implemented` | `NOT_IMPLEMENTED` | Endpoint contract defined, implementation scheduled for future phase. |
| `503 Service Unavailable` | `SERVICE_UNAVAILABLE` | Database or critical internal dependency is unreachable. |

## 5. Pagination, Sorting, and Filtering Standards

### Pagination Conventions
- Query parameters: `?page=1&per_page=20`
- `page`: Minimum `1`, default `1`.
- `per_page`: Minimum `1`, default `20`, maximum `100`.
- Invalid or negative values are automatically clamped or rejected with `422 VALIDATION_ERROR`.

### Sorting Conventions
- Query parameters: `?sort_by=created_at&sort_order=desc`
- `sort_by`: Strictly restricted to allowlisted column names per endpoint (e.g., `created_at`, `appointment_date`, `name`, `status`). Arbitrary column names from clients are never injected into queries.
- `sort_order`: Strictly `asc` or `desc` (case-insensitive).

### Filtering Conventions
- Field equality: `?status=confirmed&dentist_id=2`
- Date range: `?start_date=2026-11-01&end_date=2026-11-30` (ISO-8601 `YYYY-MM-DD`).
