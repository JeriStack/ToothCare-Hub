## 1. Project Risk Register

| Risk ID | Risk Description & Root Cause | Likelihood | Impact | Severity | Preventive Controls | Detection Method | Contingency / Recovery Plan | Responsible Role (Named Owner) | Status & Review Date |
|---|---|---|---|---|---|---|---|---|---|
| `RSK-001` | **Double Booking / Concurrency Race Condition:** Two patients or staff members submit overlapping appointment requests for the same dentist simultaneously, or variable service durations overlap part of an existing slot. | Medium | Critical | **High** | 1. Wrap booking creation/rescheduling in an InnoDB transaction.<br>2. Execute `SELECT dentist_id FROM dentists WHERE dentist_id = ? FOR UPDATE` to serialize writes per dentist.<br>3. Validate interval overlap (`existing.start_at < req_end AND existing.end_at > req_start`) across all `PENDING` and `CONFIRMED` rows.<br>4. Disable repeat-submit buttons in React. | Automated concurrent booking integration test in PHPUnit; database constraint/overlap checks; Prometheus conflict counter metric. | Roll back losing transaction immediately and return `409 Conflict` (`SLOT_UNAVAILABLE`); UI refreshes available slots and prompts user to pick a new time. If a bug ever allowed a duplicate in prod, Admin cancels one booking with an audited reason and contacts the patient. | Lead Backend Architect / Project Owner | Open — Review at Phase 4 & Phase 10 |
| `RSK-002` | **SMTP Outage, Delayed Email, or Failed Delivery:** External SMTP provider is unreachable, rate-limited, or slow during booking creation or admin approval, potentially blocking HTTP responses or losing notifications. | Medium | High | **High** | 1. Never call SMTP synchronously inside the booking HTTP request if it can block/rollback the transaction.<br>2. Persist `email_outbox` and in-app `notifications` rows in the same MySQL transaction as the appointment.<br>3. Process `email_outbox` asynchronously via `ProcessEmailOutbox` worker with exponential backoff and max retry limits, distinguishing transient (`4xx`/timeout) from permanent (`5xx` invalid recipient) errors. | Prometheus `EmailOutboxBacklog` alert; `email_outbox` status monitoring (`FAILED_RETRYABLE`, `FAILED_PERMANENT`); worker error logs. | Users still see immediate in-app notifications via REST and Socket.IO; once SMTP connectivity is restored, the worker drains pending retryable jobs without duplicating appointments. | Backend / DevOps Lead | Open — Review at Phase 13 |
| `RSK-003` | **Unauthorized Real-Time Event Subscriptions or Data Leakage:** Malicious or buggy clients attempt to join another user's, dentist's, or admin's Socket.IO room, or sensitive clinical data is broadcast over WebSockets. | Medium | Critical | **High** | 1. Authenticate Socket.IO handshakes using short-lived signed tickets issued by the authenticated PHP API (`/api/v1/realtime/ticket`).<br>2. Assign rooms strictly server-side (`user:<id>`, `role:admin`, `dentist:<id>`); ignore any client-supplied room join requests.<br>3. Authenticate PHP-to-Node internal publishing (`/internal/publish`) on the private network using `REALTIME_INTERNAL_SECRET`.<br>4. Send minimal event payloads (IDs, status, timestamps only) and fetch details over RBAC-protected REST endpoints. | Automated security tests (`realtime/tests/events.test.js`) testing forged room joins, expired tickets, and unauthenticated connections; Socket.IO auth failure metrics. | Revoke/rotate `REALTIME_INTERNAL_SECRET` and session tickets; disconnect unauthorized sockets on logout; rely on REST `/api/v1/notifications` if `realtime` service is isolated. | Security Engineer / Backend Lead | Open — Review at Phase 14 |
| `RSK-004` | **Exposure of Private Patient or Clinical Treatment Information (IDOR / Logs / Metrics / Public Assets / PHP Runtime RCE):** A patient accesses another patient's record by changing a URL ID, diagnosis notes/credentials leak into logs/metrics, or unpatched PHP vulnerabilities (`CVE-2026-109618`, `CVE-2026-109619`, `CVE-2026-115560`) are exploited. | Low–Medium | Critical | **High** | 1. Pin PHP to `8.5.12` and set `session.upload_progress.enabled = Off` & `expose_php = Off` (already enforced in `docker/php/Dockerfile`).<br>2. Centralize RBAC and resource-ownership checks in PHP (`patient.user_id === session.user_id`, `appointment.dentist_id === session.dentist_id`).<br>3. Exclude `treatment_records` from emails and WebSocket payloads.<br>4. Redact passwords, tokens, and clinical text from structured logs and Prometheus labels.<br>5. Set Nginx document root strictly to `backend/public`. | Negative authorization tests (`401`/`403` for cross-patient and cross-dentist access); `git status` / `.dockerignore` checks; CI secret scanning. | Immediately block offending endpoint/route, rotate any exposed secret/token, purge sensitive log lines, and audit `audit_logs` for unauthorized access scope. | Security & Privacy Lead | Open — Continuous across all phases |
| `RSK-005` | **Local vs. Production Deployment Incompatibility (Windows XAMPP MariaDB 10.4 vs. Docker MySQL 8.x / Compose CLI):** Differences in SQL syntax between local XAMPP (`10.4.32-MariaDB`) and container `mysql:8.0`/`8.4`, port collisions (`80`/`3306`), or missing `docker compose` CLI plugin on Windows host. | Medium | High | **High** | 1. Write portable InnoDB SQL migrations compatible with both MySQL 8.x and MariaDB 10.4.<br>2. Map Nginx to `8080:80` in `docker-compose.yml` to avoid XAMPP Apache port `80` conflicts.<br>3. Pin PHP (`8.5.12`), Node (`20`/`22`), MySQL (`8.0`/`8.4`), and Nginx (`1.27-alpine`) versions and commit lockfiles (`composer.lock`, `package-lock.json`). | CI pipeline validation (`.github/workflows/ci.yml`), `scripts/check-project.ps1`, and staging smoke tests (`deployment/scripts/health-check.sh`). | If Socket.IO cannot run on a constrained host, React notification center degrades gracefully to REST polling (`GET /api/v1/notifications`); for container deployment issues, roll back via `deployment/scripts/rollback.sh`. | Technical Project Manager / DevOps Lead | Open — Review at Phase 2 & Phase 20 |
| `RSK-006` | **Scope Creep Delaying Core MVP Delivery:** Adding multi-service appointments, online payments, SMS reminders, or full EHR charting before core booking and RBAC are verified. | Medium | Medium | **Medium** | Freeze MVP scope in `docs/phase-0/mvp-scope.md`; enforce vertical slice completion and PR checklist gates. | Weekly backlog/PR review against `mvp-scope.md`. | Defer non-MVP enhancements to post-Phase 23 backlog. | Technical Project Manager | Open — Continuous |

## 2. Assumptions Register

| Assumption ID | Assumption Statement | Impact if False | Owner |
|---|---|---|---|
| `ASM-001` | ToothCare Hub MVP operates for a single dental clinic in a single canonical time zone (`Asia/Manila`, `UTC+08:00`). | Would require per-branch time zones and branch-scoped schedules/dentists. | Clinic Owner |
| `ASM-002` | Each appointment request in the MVP covers exactly one dental service (`service_id`), whose duration determines the slot length. | Would require an `appointment_services` junction table and summed duration calculation. | Clinic Owner |
| `ASM-003` | The target staging/production environment supports Docker Compose (or equivalent Linux containers with Nginx, PHP-FPM, MySQL, Node.js, and CLI workers). | Basic PHP-only shared hosting cannot run Socket.IO, Prometheus, or Grafana containers natively. | DevOps / Project Sponsor |
| `ASM-004` | An authenticated SMTP test sink (e.g., Mailpit/Mailtrap) or mock mailer will be used in development/CI, and a transactional SMTP provider will be supplied via environment variables in production. | Outbox jobs will remain queued if no SMTP server is reachable. | DevOps Lead |
| `ASM-005` | All development, testing, seed scripts, and OpenAPI examples will use 100% synthetic data; no real patient PII will be entered prior to formal privacy compliance sign-off. | Real patient data would trigger strict regulatory/legal obligations under RA 10173 immediately. | All Team Members |
